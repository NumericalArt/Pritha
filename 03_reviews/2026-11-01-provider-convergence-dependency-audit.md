## Remaining Zod finding

The application directly pins patched Zod 4.6.6. The latest registry version of
`@anthropic-ai/sandbox-runtime` is still 0.0.81 and requires Zod `^3.25.0`.
The registry reports no compatible fix. Forcing Zod 4 into that dependency would
change an isolation-critical API without upstream support, so this audit does
not do that or call the residual finding resolved.

The vulnerable behavior is excessive allocation while validating oversized
collections. Reachability review found exactly one sandbox-runtime import in
the host sandbox launcher. Its configuration is generated by
`scripts/lib/provider-sandbox.mjs`; model input is never passed directly to the
dependency's schema. Host limits include 32 read roots, 10 immutable roots,
16 write roots, 256 protected paths, 2 loopback slots and 128000 argv bytes.
`provider-sandbox-run.mjs` accepts only a regular, single-link, owner-only plan
file owned by the current user, at most 256000 bytes. The model process cannot
read or replace that plan. Domains, permissions and weaker-isolation flags are
host-authored constants; this boundary is covered by the real OS escape tests.

This limits the attacker-controlled input path; it is a mitigation assessment,
not an upstream patch or a claim that every use of Zod 3 is safe. Re-evaluate
when the runtime publishes a compatible fix, the plan boundary changes, or a
model-facing schema is introduced. No scheduled monitor or service was created.

# Ручная проверка Brief Desk ND

## Локальный запуск и демо

1. Из папки импортированного агента запустите `node server.mjs` в терминале.
   Оставьте терминал открытым; для завершения нажмите Ctrl+C. Фоновый сервис
   для этой проверки не нужен.
2. Откройте адрес из строки `Brief Desk ready`. По умолчанию это
   `http://127.0.0.1:3435`; собственный `BRIEF_DESK_ND_PORT` меняет порт.
3. Откройте «Настройки · NeuralDeep и Telegram». В новой установке должны отсутствовать ключи NeuralDeep
   и Telegram. Агент использует только собственные настройки.
4. Нажмите «Открыть демо без ключей». Должен появиться синтетический бриф со статусом ready,
   заголовком, пунктами и источниками. Ключи и сеть для демо не нужны.
5. Измените заголовок или пункт, сохраните и перезагрузите страницу.
   Правка должна сохраниться. Повторное открытие демо не должен её затереть.
6. Повторный импорт через Pritha должен вернуть already-installed и сохранить
   проект, собственные настройки и историю. Это проверка идемпотентности,
   а не команда сброса или обновления пользовательских файлов.

## Проверка подключённого провайдера

Собственный ключ вводится в настройках этого агента. После сохранения проверьте
подключение, введите тему и запустите сборку через интерфейс. Статусы должны
пройти searching → fetching → drafting → ready. Прочитайте источники и
проверьте, что пункты брифа подтверждаются ими. При draft_unavailable должна
отображаться понятная ошибка; успешный результат не подменяется демо.

## Необязательная публикация

Настройте собственное назначение по [инструкции Telegram](telegram.md).
Проверка доступа не отправляет сообщение. Тестовое сообщение и публикация
брифа — отдельные действия, требующие явного подтверждения владельца.
Перед публикацией ещё раз проверьте текст, текущую редакцию и назначение.
При delivery_unknown сначала проверьте канал; не повторяйте отправку вслепую.

Ручные POST-запросы без CSRF-токена, идентификатора запроса и актуальной
редакции не заменяют этот сценарий. Используйте интерфейс, который передаёт
необходимые поля. Для локальной автоматической проверки запустите `npm test`:
она использует временные данные и не отправляет реальные сообщения.
